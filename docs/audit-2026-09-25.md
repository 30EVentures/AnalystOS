Scope: the repository at `main` @ `9c82765`. Every finding below was checked by
reading the code, running it, or running its tests — not by trusting `README.md`,
`ROADMAP.md`, `docs/decisions.md`, or the public homepage. Where a claim could not
be checked from inside this repo, it is listed under "Could not verify" rather than

## 1. The short version

- **CONFIRMED — 503 of 503 tests pass** on a fresh run (`python3 -m unittest discover -s tests`, ~2.0–2.2 s, 39 test modules). The homepage's "503 / 503 … 2.3 seconds" is accurate.
- **CONFIRMED — the core idea is real and enforced in code:** every quote must be a substring of the source, every calculation is recomputed by the software, unproven facts are dropped, the writer cannot emit a digit outside a `{{N}}` placeholder, two independent gates run, and a zero-model template tier now exists underneath the written report.
- **CONFIRMED — what the verification does *not* prove is wider than the marketing says.** It proves each *number*. It does not prove the *sentence that connects numbers* (finding 1 below — with a real example that passed both gates). "Every number is proven" is true; "a report should never contain a number nobody can defend" is stronger than what the code checks.
- **CONFIRMED — several public claims are overstated or mis-scoped** (privacy wording, tags "wherever a figure appears", image-derived tag, server-generated PDF, "a report is never lost", "each spec has a retrospective", live-suite "real documents"). Full table in §6.
- **CONFIRMED — the documentation is badly stale** in places (`docs/architecture.md` says "Nothing built yet"; `ROADMAP.md` stops at Slice 28 of 54; README says "No third-party packages yet"; five slices of real code have no spec).
- **CONFIRMED — the AAO validator (`analystos/aao/validate.py`) is a loose stand-in**, imported by nothing except its own test, and disagrees with the *published* AAO JSON Schema on **15 of 21** probe documents. The one real manifest passes both. (Details: `docs/flashyos-alignment-2026-09-25.md`.)

## 2. Ranked findings

Ordered by how much a public claim depends on them.

### 1. Verified numbers ≠ verified claims (CONFIRMED, most important)

The real Orion run (`jobs/orion/section.html`, passed Gate 1 **and** Gate 2) contains:

> Gross margin moved (4.7%) points to 54.2% **from 55.8%**

Source data: gross margin 58.9% → 58.0% → 57.1% → 55.8% → 54.2%. The `(4.7%)` is a real, correctly-recomputed *four-quarter* change (58.9 → 54.2). `55.8%` and `54.2%` are real, correctly-cited quotes. But 55.8 → 54.2 is **1.6** points, not 4.7. Every number is individually proven; the sentence joining them is wrong, and nothing in the pipeline can detect that (Gate 1 checks digits, placeholders, direction words, consecutive-count claims; Gate 2 is deliberately blind to facts).

The homepage "Sample brief" (described as "condensed from a system run") shows the corrected wording — "fell 1.6 points" — so the sample is *cleaner than the raw output*. (Separately, that wording pairs a direction word with a point-change; if that figure is a `difference` fact, as margin changes in points normally are, Gate 1's direction-word rule would flag it — I did not re-run the sample through the validators to confirm.) The sample is disclosed as "condensed"; it is not disclosed as "edited to remove an error".

### 2. "Cannot type a number" only covers digits (CONFIRMED by running `_validate_paragraph`)

| Paragraph | Result |
|---|---|
| `Revenue reached {{0}}, up 25% year over year.` | rejected (digit outside placeholder) |
| `Revenue grew twenty percent to {{0}}.` | **accepted** |
| `Revenue roughly doubled to {{0}}.` | **accepted** |
| `About two-thirds of the growth came from one segment, reaching {{0}}.` | **accepted** |
| `Revenue rose by nearly a third, to {{0}}.` | **accepted** |

`_NUMBER_WORDS` exists only inside the consecutive-quarters check. Spelled-out or fractional quantities are unchecked, and Gate 2 cannot catch them (it does not see the data). The Meridian source itself contains "approximately two-thirds", so this arises naturally.

### 3. Privacy wording describes the local CLI, not the hosted site (CONFIRMED)

- Homepage: "**Stays on your machine** — The original file and the encrypted evidence store", and pipeline stage L0: "Your file is saved once, named by the SHA-256 fingerprint… and encrypted at rest" (tagged "Runs locally").
- Reality on the hosted upload path: `api/analyze.py` writes the upload to a temp dir and `shutil.rmtree`s it ("never keep the upload"); the extracted text goes to Anthropic's API. So on the hosted site the file is **not** on the user's machine and **not** retained.
- `site/upload.html` says "Nothing you upload is stored; each request is processed and discarded" (accurate) and "analyzed by a model" — **NOT FOUND:** any statement that document text is sent to a third party (Anthropic). Only the homepage FAQ says so.
- The homepage never distinguishes "run it yourself" from "use the hosted upload page" — the page that invites uploads.

### 4. Encryption at rest is real but the default key is public (CONFIRMED by test)

Stored bytes are Fernet ciphertext (plaintext not visible; round-trips). But with no `ANALYSTOS_EVIDENCE_KEY` set, the key is derived from a constant printed in `analystos/l0/store.py` — I decrypted a stored file using only that constant. The code comments call it a dev fallback. **CLAIMED, UNVERIFIED:** that the Vercel deployment sets the env var (not checkable from the repo). On the hosted path the point is moot (nothing is retained), which is itself an inconsistency with "encrypted at rest" as a headline feature.

### 5. GAAP / non-GAAP / guidance tags are not "wherever a figure appears" (CONFIRMED by rendering)

Rendered a report with a non-GAAP KPI, a guidance KPI and a chart mixing non-GAAP and GAAP bars:

| Surface | Basis tag shown? |
|---|---|
| Body paragraphs (HTML) | yes |
| Body paragraphs (PDF) | yes |
| **KPI strip (HTML)** | **no** |
| **KPI strip (PDF)** | **no** ("Adj. NI Guide / $63.5M $1.9B") |
| **Chart bars** | **no** |

Also: `horizon` and `gaap_status` are labels the *model* assigns and no code checks against the source; `_horizon()` defaults a missing/unknown value to `"reported"`. So "a figure is tagged GAAP only if the source says so" and "forward-looking figures are visibly tagged" depend on the model following its prompt, not on enforcement.

### 6. The image-derived tag is never rendered (CONFIRMED; my own Slice 50 gap)

`tag_image_sourced_segments` sets `segment["source"] = "image"`. A search of every renderer in `analystos/l4/` finds **no code that reads it**. Slice 50's spec promised such facts would "render visibly distinct — never silently indistinguishable"; its "Built" note does not disclose that this was not built. The homepage says image facts are "tagged as image-derived" — true in metadata, invisible to a reader. (Also: the vision step transcribes *visible text in* an image; the homepage's "charts embedded in PDFs are transcribed" reads as if chart data is extracted, which the spec explicitly excludes.)

### 7. The server-generated PDF is not exposed by the hosted API (CONFIRMED)

`render_rich_pdf` and `build_report(want_pdf=True)` exist and are tested; the CLI writes `section.pdf`. `api/analyze.py` never passes `want_pdf` and returns only `section` + `html`; the report page's PDF button is the browser's print dialog. The homepage lists "a real server-generated PDF … not a print-to-PDF" under "Delivery — Built" without saying it is CLI/library-only.

### 8. "A report is never lost" is false when extraction fails (CONFIRMED by forcing it)

The fallback tiers start *after* `analyze_document` succeeds. Forcing extraction to return nothing verifiable → `ValueError: no verifiable content survived…` and no report. Forcing an API connection error on the first call → `ValueError: analysis is temporarily unavailable…` and no report (the API returns HTTP 400). Accurate wording: "never lost once facts are verified."

### 9. The live suite is thinner than it reads (CONFIRMED)

- "PASS" means `build_report` did not raise (`run_live_tests.py::_run_one`). It does not check which tier ran, whether the rich narrative passed, or whether the image fact was extracted. Since Slice 52, a document that fails both gates still "passes".
- The four fixtures are **invented** (`live_tests/build_fixtures.py` generates them); the homepage says "four fixed real documents". One of the four is a CSV on the no-model path, so three make paid calls.
- Cost data is **one** full run ($0.2668) plus one deliberately-aborted run — "typically a few cents to a few tens of cents" is n = 1.
- "Typically 3 model calls per report" (homepage, and the value-calculator's assumption): the one full run used 5, 3 and 8 calls (8 includes 1 vision call) on the three narrated documents.

### 10. Process claims (CONFIRMED)

- Homepage: "49 written specs… each with a 'done when' and a retrospective." → 49 folders but **48** `spec.md` (`specs/slice-14/` is empty); **48/48** have "Done when" ✓; only **22/48** have any retrospective-like section ("Verified beyond the test suite" or "Built (post-implementation)"); **26/48 have none** (slices 1–19 and 40–47).
- "Writing a spec before every piece of code" → **Slices 35–39 have no spec at all** (v4 data, v4 renderer, Download-PDF, Gate 1 + Gate 2, growth-percent order — i.e. both quality gates). `specs/slice-38/spec.md` is cited in code and does not exist.
- "Written before the code" cannot be verified from git: in 40 of 48 cases the spec first appears in a commit that also contains product code.
- "Dozens of defects logged with root cause": the decision log has 50 entries, ~12 of which describe a live-found defect or root cause, plus 20 "Found live" code comments. A dozen-plus is fair; "dozens… with proof of the fix" is generous. (The `$7.6M` anecdote and the 1 m 38 s timing anecdote are both real and present in the log.)

### 11. Non-determinism is real and unmeasured (CONFIRMED from logs)

Same Meridian document, three runs: 21, 23, 27 verified segments. The same Orion document passed the rich narrative locally and fell to the deterministic floor on a live run. There is **no recall measurement** (how many real figures never get extracted) and no writing-quality benchmark — the homepage says so, correctly.

### 12. Smaller confirmed items

- **Display rounding** uses Python float formatting: `$1.95B` shows as `$1.9B`, `$1.25M` as `$1.2M`, `12.35%` as `12.3%` but `12.25%` as `12.2%`. Footnotes carry the exact source text, so it is traceable, but it is a displayed-number inaccuracy in a product about displayed numbers.
- **Rate limiting is in-memory, per process** (`api/analyze.py`): disclosed in the code comment, not on the homepage; weak across serverless instances.
- **`analystos/aao/validate.py` is dead code** — no product module imports it.
- **Model:** every call uses `claude-sonnet-5` (analyze, narrate, proofread, image transcription) — matches the homepage.

## 4. Built, but quality-unverified

Code exists and its tests pass; whether it works well on *real* input is unmeasured.

- **AI writing quality** — no benchmark; Gate 2 is a model judging prose blind to facts. (Homepage says so.)
- **Extraction completeness (recall)** — unmeasured; run-to-run variance in verified-fact count is large (21/23/27).
- **Column detection** — tested only on synthetic PDFs built with `reportlab`; not on a real multi-column filing. One gutter only; 3+ columns and tables-inside-columns are untested.
- **Image transcription** — tested on a synthetic PNG of rendered text; fidelity on real charts/exhibits is unmeasured. One live "PASS" exists (see finding 9 for what PASS means).
- **Boilerplate stripping / footnotes** — heuristics validated on constructed fixtures.
- **Deterministic tier prose quality** — reviewed by eye on two real documents; two real-document bugs (label parsing, wrong-quarter attachment, a 2-point "bridge") were found *after* all tests passed, which says the fixtures under-represent real label variety.
- **Rich PDF visual fidelity** — tests assert structure (page count, fonts, fills, no split chart), not appearance.
- **Rate limiting under serverless** and **encryption key configuration on Vercel** — see finding 4/12.

## 7. What the 503 tests do and do not establish

- **All mocked.** No test touches the network or a real model. That is why they are fast and free — and why they cannot catch the class of bug that only real model output produces. The project already learned this (Slice 51 built a separate live tier; Slices 53–54 were found by real runs).
- **Fixtures are synthetic.** Column layouts, images, footnotes, boilerplate and label formats are constructed by the tests' authors. The label formats that broke the deterministic tier ("Q2 FY2027") were not in any fixture.
- **They verify code paths, not usefulness.** A green suite means the validators, renderers and fallbacks behave as specified — not that reports are good or complete.
- **The live suite** (manual, paid, $1 cap) adds real-model coverage but asserts only "did not raise" (finding 9).
