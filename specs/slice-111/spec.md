# Slice 111 - the homepage's test and spec figures say what they actually count

## Goal

A fresh-context review of Slice 108 found two wrong public numbers on
`site/index.html`. Both predate the rebuild.

1. **"N automated tests passing" counts tests that never ran.**
   `tools/site_counts.py` (Slice 69) sets the figure from
   `suite.countTestCases()`, which counts every discovered test. That includes
   the 14 tests behind `@unittest.skipUnless(...)`, which are skipped on a
   machine without Node.js or without `npm install` in `tools/flashyos-check/`
   or `mcp-server/`. Five places on the page call that number "passing", and
   the evidence card says "N / N".
2. **The hero says "49 written specs behind the build"; the evidence card says
   102.** No generator owned the hero figure. It was typed by hand at
   Slice 49 or earlier and never changed. Slice 69's patterns cover only the
   evidence card.

## Approach

**Tests: say what the number is.** Do not count passes. The skips depend on
the machine, so a "passing" count would change with whoever ran the generator,
and `--check` would pass on one machine and fail on another. Counting passes
would also mean running the whole suite from `site_counts.py`, which the suite
itself calls through `tests/test_site_counts.py`. The discovered count stays.
It is deterministic, offline and cheap. The words around it now describe it:
"automated tests in the suite", with no claim that every one of them passes.
The "N / N" pair goes. A note says that tests needing Node.js are skipped where
it is not installed.

**Specs: one source.** The hero figure gets its own pattern in
`site_counts.py` with kind `specs`. It is now generated from `count_specs()`
(the `specs/slice-N/spec.md` files), the same source as the evidence card.

## Not in this slice

- Running the suite to count passes (see above).
- Any other page's wording. `docs/audit-2026-09-25.md` quotes the old "49" as
  history and stays as it is.

## Done when

1. No figure on the homepage that `site_counts.py` generates says "passing",
   and no "N / N" pair remains. A test enforces this.
2. The hero's "written specs" figure is generated by `site_counts.py` from
   `count_specs()` and agrees with the evidence card. A pattern that stops
   matching fails the tool, as in Slice 69.
3. `python3 tools/site_counts.py --check` and `python3 tools/refresh.py --check`
   are clean.
4. `python3 tools/flashy_freeze.py --check` holds. The fence is not moved.
5. Full suite OK.
