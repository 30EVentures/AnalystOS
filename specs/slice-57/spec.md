# Slice 57 - public claims match what the code does

## Goal

`docs/audit-2026-09-25.md` findings 3, 4, 8 and 10 and its docs-vs-code table.
Several statements on `site/index.html` and `site/upload.html` described the
local command-line tool as if it were the hosted upload page, or promised more
than the code checks. The FlashyOS plan (`ROADMAP.md`, R1) says AnalystOS
should not ask anyone else's agents to rely on it while its own public claims
are wrong.

Changed (copy only, no behaviour):

- "Stays on your machine" and "Runs locally" described the CLI. Now: "No
  model call" for steps that make none, and separate statements for a local
  run (file and encrypted store stay on your machine) and the hosted page
  (file uploaded, processed in a temp folder, deleted at the end of the
  request, extracted text sent to Anthropic).
- "Encrypted at rest" now says the key is one you set, and that without one a
  development key that is public in the source is used.
- "GAAP... wherever a figure appears" / "tagged GAAP only if the source says
  so" now say the labels come from the writer model and are not checked in
  code, and that the tags appear on text, KPI tiles, chart notes and
  footnotes (Slice 56).
- "A report is never lost" now says a report degrades but a file that cannot
  be read produces none.
- "real server-generated PDF": the code can generate one; the hosted page
  returns HTML with a print button.
- "four real documents" -> "four fixed test documents" (they are generated by
  `live_tests/build_fixtures.py`); "each with a retrospective" removed (not
  true of every spec).
- Known limits gains three items: relationships between figures are only
  partly checked; runs are not deterministic; the hosted page has no durable
  link, history or audit trail.
- `site/upload.html` says the extracted text goes to Anthropic's API and asks
  for non-confidential documents only.

- Exposing the PDF from the API (Slice 61 does).
