# Slice 94 - the handshake declares the charter's role names

## Goal

The Flashy estate's own 21 Nov 2026 reply to the owner's integration plan resolved a
question `docs/mesh-identity.md` had left open since Slice 59: their `auditProperty`
checker grades a handshake with no `capabilities` array at level 1 ("declares nothing
it can do"), which looked like it conflicted with this repo's rule of withholding
capabilities until something is callable. Their reply distinguishes two different
claims that had been conflated under one word:

- a **role name** (`analysis`, `verification`, `evidence`) restates a governance fact
  the charter already publishes, and claims nothing callable;
- a **discovery slug** (`document-analysis`, `figure-verification`, ...) claims an
  endpoint exists and can be called.

Declaring the first kind costs nothing and is correct under this repo's own doctrine.
Declaring the second kind before the endpoint and a token exist would be exactly the
gamed-metric failure `docs/mesh-identity.md` was written to avoid, and this slice does
not do that.

## Done when

1. `site/.well-known/flashyos.json`'s `capabilities` array is exactly the charter's
   role names, generated by a tool, never hand-typed.
2. The tool (`tools/build_flashyos_handshake.py`) has a `--check` mode wired into
   `tools/refresh.py`, so a hand-edit that drifts from the charter fails the suite.
3. The real, published `@flashyos/aao` and `@flashyos/conformance` packages - not a
   local re-implementation of their rules - confirm `validateCharterDocument` returns
   no errors and `auditProperty` returns `{ok: true, issues: [], level: 2}` against
   the served charter and handshake together.
4. The same real validator, run against the handshake with `capabilities` removed,
   reports level 1 - proving check 3 is not vacuous and reproducing the exact finding
   Flashy's reply described.
5. `tests/test_mesh_identity.py`'s old safety-net test (`capabilities must be absent`)
   is replaced with tests that assert the new, narrower rule (role names only, no
   discovery slugs) rather than simply deleted.

## Not in this slice

- Declaring the discovery slugs (`x-capability` values) in the handshake. That still
  needs a deployed, token-gated endpoint per every role, which this slice does not add.
- Minting an agent token, declaring capabilities on the live FlashyOS org, or anything
  else that calls `api.flashyos.com`. This slice only changes files in this repository.
- Deciding whether the live charter should grow from three roles to the seven-role
  team charter Flashy also validated on 21 Nov. That is a separate decision; see
  `site/.well-known/flashyos-charter.team.json` (draft, not served) and the Blocked
  list in `ROADMAP.md`.

## Note on process

Written after the code, not before, which breaks this repo's own stated convention
(`CLAUDE.md`: "a `specs/` folder written *before* any code"). The tool and its tests
were built first in this session while confirming the real validators' behaviour
end to end; this spec was then written to record what was actually built and checked,
honestly out of order rather than backdated to look otherwise.
